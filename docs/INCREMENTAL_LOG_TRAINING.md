# 운영 로그를 이용한 점진적 개선

로그가 쌓이는 것만으로 모델 가중치가 바뀌지는 않는다. 기존 도구를 재사용해
**새 사진 선별 → 자동 라벨 검증 → 후보 재학습 → 기존 모델과 비교**로 진행한다.
API 응답과 Spring 계약은 바꾸지 않는다. 검증에 실패하면 기존 모델을 유지한다.

## 간단하게 유지할 운영 방식

1. 원본 이미지와 JSON이 모두 저장된 로그를 고정된 스냅샷으로 확보한다.
   원래 날짜/파일 상대경로를 유지한다. 수집 중인 폴더를 학습 입력으로 직접 쓰지 않는다.
2. `prepare_operational_capture_queue.py`로 2026-08-01 00:00 KST 이전 운영 사진,
   중복, 읽을 수 없는 사진, 저해상도·극단 노출을 제외한다. 기존 학습 SHA와 보호 검증
   SHA는 새 teacher 큐에 재투입하지 않는다. 기존 `val` 표기는 원본 해시를 기록한 새
   audit에서 `protected_validation`으로 정규화할 수 있지만 원본 audit는 수정하지 않는다.
3. `label_operational_captures_ollama.py`는 모델·프롬프트 계약과 이미지가 일치하는
   완료 결과만 캐시에서 재사용한다. 새 이미지와 불완전한 실패만 다시 판정한다.
   기존 AI 예측 결과를 정답으로 복사하지 않는다. 촬영 품질에 대한 주관적 합의와
   독립된 두 위치 검출기의 bbox 합의를 통과한 데이터만 후속 학습 후보로 사용한다.
4. 검증된 운영 데이터를 기존 AI Hub 9종 데이터와 소량 섞어 후보를 재학습한다.
   클래스별 성능, 비닐/플라스틱·종이/스티로폼 혼동과 빈 장면 오검출을 비교한다.
   고정 하드웨어 41장은 진단/보정용이다. 신규 독립 blind 및 실제 하드웨어 종단 검증
   전에는 production/Pi 모델을 교체하지 않는다.

실시간 온라인 학습, 자동 배포, 별도 플랫폼은 추가하지 않는다. 새 데이터가 충분히
쌓였을 때 동일한 절차를 다시 실행하는 배치 방식이다. 데이터가 많아져도 오라벨이나
분포 편향이 늘면 성능이 떨어질 수 있으므로 개선을 보장하지 않는다.

## 재사용 캐시

기존 teacher 명령에 선택적으로 다음 인자를 추가한다.

```text
--checkpoint-dir /app/operational_teacher_cache
```

캐시는 `<checkpoint-dir>/<teacher-contract-sha>/<image-sha>/<payload-sha>.json`으로
분리된다. 새 배치에는 새 `--output` 경로를 사용한다. 모델 또는 프롬프트 계약이
바뀌면 이전 캐시를 재사용하지 않는다. 파일 내용과 상대경로도 다시 확인하며,
같은 SHA라도 상대경로가 달라지면 재판정한다. 경로를 보존한 스냅샷을 권장한다.

출력 요약의 `reused`, `newly_labeled`, `retried`, `image_error`로 처리량을 확인한다.
`retried`는 새 판정을 시도한 항목 중 재시도 부분집합이므로 단순 합산하지 않는다.
캐시 자동 삭제는 없으며 NAS의 별도 디렉터리에 두고 용량을 확인한다. 모델 캐시는
학습 결과나 배포 승인 증거가 아니며, 서로 다른 VLM의 독립 검증을 대신하지 않는다.

이 옵션을 생략하면 기존 출력 파일별 checkpoint 방식이 유지된다. 공유 캐시 모드의
출력은 덮어쓰지 않으며, symlink와 출력/캐시 경로 충돌을 거부한다.

## 현재 범위

- 원본 이미지·무게·응답 저장 기능은 기존 `request_capture.py`에 구현되어 있다.
- 증분 캐시는 teacher 판정 비용을 줄이는 기능이다. 스케줄러나 자동 재학습을 새로
  설치하는 기능은 아니며 서버에서 실행해야 효력이 있다.
- 현재 운영 teacher manifest에서 압착(`dent`)과 라벨(`label`)이 미확정인 항목은
  `-1`로 마스킹된다. 재질·이물질 데이터 증가를 모든 상태 헤드의 개선으로 표현하지 않는다.
- 모델 모니터링과 별도 검증 후 재학습 원칙:
  [Ultralytics 공식 안내](https://docs.ultralytics.com/guides/model-monitoring-and-maintenance/).
