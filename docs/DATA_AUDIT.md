## 1. 점검 결과

| 구분 | 이미지 | 라벨 파일 | 빈 라벨 | 객체 합(로그) | 객체/이미지 |
|------|--------|-----------|---------|---------------|-------------|
| **train** | 804,421 | 804,421 | **0** | 518,728 | 0.64 ⚠️ |
| **val** | 47,826 | 47,826 | — | 68,147 | 1.43 ✅ |

- 이미지 ↔ 라벨 파일 수 **정확히 일치** (짝 깨짐 없음)
- 빈 라벨 파일 **0개** → "객체 없는 배경 이미지" 오학습 우려는 **없음**
- val은 1.43 객체/이미지로 **정상**

## 2. 이상점

**train 파일 수(804,421)가 변환 로그의 객체 합(518,728)보다 많다.**

빈 라벨이 0인데 파일이 객체보다 많은 건 모순 → **변환 로그를 남긴 실행(재실행) 외의 파일이 디렉토리에 누적**됐다는 의미.

### 역산
- val 비율(1.43 객체/img)을 train에 적용 → 정상 파일 ≈ 518,728 ÷ 1.43 ≈ **364,000**
- 이는 재실행 변환량(361,597 페어)과 **거의 일치** ✅
- 잔여 = 804,421 − 364,000 ≈ **약 44만 파일이 이전 실행 잔여**

## 3. 원인 (추정)

- 종이 0쌍 문제로 **첫 실행 → 중단 → 재실행** 과정에서, 첫 실행 결과(`yolo_dataset_9class_v2`)를 `sudo rm` 했으나 **완전히 지워지지 않았거나**, 8일 경과 중 추가 실행이 누적된 것으로 보임.
- 두 실행의 파일 stem(`train_0000000…`)이 인덱스 범위가 달라 덮어쓰이지 않고 **잔여로 남음**.
- val은 영향 없음 (val 디렉토리는 깨끗하게 재생성됨).

## 4. 영향

- 빈 라벨이 아니므로 **치명적이진 않음** (모든 잔여 파일도 객체 보유)
- 그러나 ⚠️ **중복/train-val 누수 위험**: 잔여 파일이 재실행 파일과 같은 원본일 수 있어, 학습 시 중복 노출 → 성능 과대평가 가능
