# 무게 기반 내부 내용물 감지 — 로직 설계 & 키오스크 파라미터

> "사진 대비 무게가 이상한 건 안에 뭐가 있거나 분리수거가 안 된 것" 을 판정하는 로직.
> 시각 분류로는 불가(내부 오염 데이터 1%뿐 + 투명 액체는 사진에 안 보임) → **무게가 정답**.
> 최종 갱신: 2026-06-20

---

## 1. 왜 무게인가 (근거)

| 방법 | 가능성 |
|------|--------|
| 시각 `이물질(내부)` 라벨 학습 | ❌ 데이터 1.1%(815장)뿐, 투명 액체 안 보임 |
| **무게센서** | ✅ 내용물을 직접 반영. 물 100ml = +100g (빈 페트병 20g의 5배) |

압착된 용기도 무게는 동일 → 변형과 무관하게 내용물만 잡아냄.

---

## 2. 로직 원리

사용자 아이디어("개수 파악 → 평균무게와 비교")를 **bbox 크기 보정**으로 정밀화:

```python
# 1) YOLO가 객체 개수 N + 각 bbox 제공
expected_empty = 0
for box in detections:
    size = bbox_to_size(box, img)          # bbox 면적/높이 → S/M/L 용량 추정
    expected_empty += EMPTY_WEIGHT[cls][size]   # 빈 용기 표준무게 합산

# 2) 실측이 예상보다 무거우면 내부 내용물
margin = SCALE_ERR + LABEL_CAP_WEIGHT + SAFETY
if measured_weight > expected_empty + margin:
    weight.anomaly = True   # "내용물 비우고 다시 넣어주세요"
```

**왜 단순 평균이 아니라 bbox 크기 보정인가:**
350ml 페트병(15g)과 2L 페트병(45g)을 평균(30g)으로 비교하면 → 2L 빈병을 "내용물 있음"으로 오판. bbox로 크기를 추정해야 정확. **이것이 사진을 쓰는 핵심 이유.**

## 3. 하드웨어 팀 확인 파라미터 ⚠️ (캘리브레이션 선결 조건)

> 아래가 확정돼야 임계값(`EMPTY_WEIGHT`, `margin`)을 실측 보정할 수 있음. **현재 전부 미확인.**

### 3-1. 무게센서
- [ ] **분해능/정밀도** (±몇 g?) → `SCALE_ERR` 결정
- [ ] **영점(tare)** 처리: 투입 전 0점 보정되는가?
- [ ] **측정 범위** (최소~최대 g)
- [ ] **안정화 시간**: 물체 안착 후 값이 안정되는 데 걸리는 시간
- [ ] 무게값 전달 형식/단위 (g? 0.1g?)

### 3-2. 카메라 ↔ 실제 크기 변환
- [ ] **카메라-물체 거리 고정 여부** → 고정이면 bbox 픽셀 ∝ 실제 크기 (선형 변환 가능)
- [ ] 해상도, 화각(FOV)
- [ ] 투입구 배경 (단색? 물체 분리 용이한가)
- [ ] 조명 일정한가 (그림자/반사)

### 3-3. 투입 방식
- [ ] **1회 1개 투입 보장?** → 보장되면 N=1로 단순화 (가장 중요)
- [ ] 여러 개 동시 투입 가능성 → 가능하면 개수 파악 정확도 검증 필요
- [ ] 투입 순서: 사진과 무게가 같은 1개에 대응하는가

## 5. margin 설계

```
margin = SCALE_ERR + LABEL_CAP_WEIGHT + SAFETY
```
| 성분 | 의미 | 값 |
|------|------|-----|
| `SCALE_ERR` | 저울 오차 | 센서 정밀도 확인 후 (예: ±5g) |
| `LABEL_CAP_WEIGHT` | 라벨·뚜껑 등 부속 무게 | 페트병 라벨+뚜껑 ~3~5g |
| `SAFETY` | 잔여물·물기 허용 여유 | ~10g (액체는 신호가 커서 넉넉해도 잡힘) |

액체 1ml ≈ 1g이라 margin을 넉넉히 잡아도 내용물은 확실히 감지됨. **보수적으로 크게 잡아 오탐(false positive)을 줄이는 방향** 권장.
